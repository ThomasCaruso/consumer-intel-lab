## Listing

- **Name:** Consumer Intelligence Lab Connector
- **Summary (≤132 chars):** Connect your own Chrome history to your private Consumer Intelligence Lab dashboard. Analysis runs on your device.
- **Category:** Education (alternative: Productivity)
- **Language:** English

**Description:**

> Consumer Intelligence Lab Connector links your Chrome browsing history to the Consumer Intelligence Lab dashboard (https://thomascaruso.github.io/consumer-intel-lab/), a student project for a Digital Marketing course. The dashboard shows how advertising platforms model consumers: interests, digital footprint, shopping style, marketing segments and recommendations.
>
> • History access is optional and requested only when you click "Approve" on the dashboard.
> • History is passed only to the open dashboard tab in your own browser. Analysis runs locally; nothing is uploaded.
> • No data is sent to any server, AI service or analytics provider.
> • Credential-like URL parameters (tokens, codes, session IDs) are removed before transfer.
> • Health, religion, politics and sexuality are never inferred; matching records are excluded.
> • The popup can capture a product's name, price and image from the page you're viewing (schema.org data), stored locally, for the dashboard's recommendation demo.
> • Revoke access at any time from the dashboard or chrome://extensions.

**Screenshots (1280×800):** capture these from the dashboard after connecting your own data, or with an empty or synthetic profile clearly labeled as a demo. Never use a fictional profile presented as real.

## Single purpose

Let the user's own Consumer Intelligence Lab dashboard analyze the user's own browsing history locally, on the user's device, to show how marketers build consumer profiles.

## Permission justifications

| Permission | Justification |
|---|---|
| `history` (optional) | Core purpose. It reads the user's own browsing history for the selected period (max 365 days) so the dashboard can analyze it locally. It is requested at runtime only after the user clicks *Approve*, and can be revoked from the dashboard. |
| `storage` | Saves products the user explicitly captures with the popup (name, URL, and price and image when the page provides them) so the dashboard can rank them. No history is stored. |
| `activeTab` | Lets the popup read the product information on the tab the user is viewing, only when the user clicks *Capture this product*. |
| `scripting` | Runs a one-time read of the active page's schema.org Product data when the user clicks *Capture*. No persistent injection. |
| Content script on the dashboard origin | A message bridge that runs only on `https://thomascaruso.github.io/consumer-intel-lab/*` (and localhost for development) so the dashboard can request data. It does not run on any other site. |

**Remote code:** none. All code is in the package. CSP is `script-src 'self'`.

## Data usage disclosures (Privacy practices tab)

- Collects: **Web history**, and for user-captured products, the **website content** of that page.
- Data is **not sold**, **not transferred to third parties**, **not used for unrelated purposes**, and **not used for creditworthiness or lending**.
- The data never leaves the user's device; the developer receives none of it.
- **Privacy policy URL:** https://thomascaruso.github.io/consumer-intel-lab/privacy.html

## Manual steps to publish

1. Register a Chrome Web Store developer account (one-time US$5 fee) at https://chrome.google.com/webstore/devconsole.
2. In the Developer Dashboard, choose **New item** and upload `store/consumer-intel-lab-extension.zip`.
3. Paste the listing text above, upload the icon and screenshots, and fill in the Privacy practices tab using the table above.
4. Choose a visibility setting. *Unlisted* is appropriate for a class project. Then submit for review.
5. After approval, put the real store URL into `CHROME_WEB_STORE_URL` in `dashboard/src/components/Connect.tsx`. Leave it as `null` until then.
